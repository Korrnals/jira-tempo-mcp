# 0001. Привести доки агента JTM и tool-контракт сервера к фактической схеме MCP

- Status: Accepted

- Date: 2026-10-30

- Deciders: `@GCW: Tech Lead` (председатель), `@GCW: Product Architect`, `@GCW: Senior System Engineer`, `@GCW: Senior Security Engineer`

## Context

Агент-специалист JTM (отчёты Jira/Tempo через MCP-сервер `jira-tempo`) отработал цикл июнь–октябрь 2026. Самопроверка выявила расхождения документации агента с фактической tool-схемой сервера: доки предписывают несуществующие параметры `date_from`/`date_to` у `generate_weekly_report`; сервер молча игнорирует лишние ключи и без корректного периода генерирует текущую неделю — вероятный механизм пропущенных недель 24–28.08, 14–18.09, 21–25.09 в каталоге отчётов. Ключевые факты подтверждены председателем лично по коду (`server.py:280–318`, `:648–675`; `_shared.py:16–20`; `config.py`).

Помимо сигнатурного разрыва, фидбек зафиксировал непрописанные правила (fallback на ручную компоновку, поведение при недоступности MCP, семантика рабочей недели — фактически пн–пт, а не Mon–Sun) и повторяющиеся ручные операции, закрываемые небольшим набором новых тулз (`week_status`, live-preview, `include_dropped`, `health_check`).

Ограничения: архитектура не меняется — все изменения аддитивны; дефолтное поведение генераторов байт-идентично; решения владельца в силе (дубли строк в подпунктах, запрет `delete_worklog`, MCP-only). Красная линия безопасности: ни один канал (лог, текст ошибки, ответ тулз) не раскрывает тело отчёта, dropped-строки или значения env/токенов; containment `_validate_output_dir` не ослабляется.

## Decision

Приводим документацию агента к фактической tool-схеме сервера и закрываем класс «тихо проигнорированный параметр» strict-валидацией; недостающие операции ритуала закрываем четырьмя аддитивными тулзами/расширениями. Конкретно:

1. **Сигнатурный фикс доков (A1, P0).** Все вызовы генераторов в трёх файлах `copilot-integration/` переводятся на `target_date` (любая дата целевой недели, default — сегодня); `date_from`/`date_to` удаляются везде, кроме `generate_team_report` (факт его схемы). `generate_tasks_report` документируется как снимок текущих задач без периодов. Рабочая неделя в формулировках — пн–пт.
2. **Strict-валидация генераторов (B5).** Хендлеры генераторов получают `additionalProperties=false` + хелпер `_reject_unknown_keys`; текст ошибки перечисляет валидные параметры. Хендлеры вне генераторов в этой волне не трогаются. B5 не мержится до A1.
3. **Новые тулзы и расширения:**
   - `week_status(username, target_date, expected_hours=40)` (B2) — read-only; окно данных пн–вс, записи сб/вс — с меткой «вне окна рендера»; норма — параметр вызова; переработка — флагом на дне (>8 ч).
   - Live-preview `preview_report_template` (B3) — параметры `live` + `target_date`; mock — дефолт; разрешён для всех шаблонов включая кастомные `.py` (исполнение уже гейтится `REPORT_TEMPLATE_ALLOW_PY`, default False; зафиксировать в security-заметке доков шаблонов); в лог — имя шаблона, число worklog'ов, длительность, никогда тело рендера.
   - `include_dropped` (B4) — у weekly- и team-генераторов: секция `Dropped lines (N)` в ответе тулзы + счётчик в лог без содержимого; json — поле `dropped`; md — всегда «(0)» (конструкционное поведение, документируется); рендер по умолчанию не меняется.
   - `health_check` (B6) — версии, конфиг-пути, статусы доступности, presence-флаги («JIRA_PAT: set»); значения env и токены — никогда, в ответе и логе на любом уровне; тест на repr/logging обязателен.
4. **Golden-гейт (до B3/B4).** Тест байт-идентичности дефолтного txt-рендера на детерминированных worklogs, покрывающий все 5 render-сайтов. Мерж B3/B4 без зелёного golden — запрещён.
5. **Ритуал полноты периодов (§Scenario 4/5 JTM_AGENT.md).** Пятница: генерация → `week_status` → сверка каталога предыдущих четырёх недель против трекинга. Триггер возврата тулзы `report_gaps` — следующий пропущенный период (тулза — следующая волна, не эта).
6. **Конфиг-контракт.** Штатная конфигурация `REPORT_OUTPUT_DIR` → корень дерева отчётов Komus (значение фиксируется живым прогоном волны); верификационный раннер — `mktemp -d` (0700), один прогон, перекрывает `REPORT_OUTPUT_DIR` и `REPORT_TEAM_OUTPUT_DIR`; корень на home/репозиторий/каталог с кредами — блокирующая ошибка конфигурации.
7. **Порядок мержа:** A1 → golden+B1 → B5 → B6 → B4 → B3 → B2 → C (док-синк). Порядок резания при нехватке ёмкости: B7 → A8; никогда A1–A6, B5, golden-гейт. Красные линии пакета: A1 и B5 неразрывны; реализация без док-синка и прогонов = незавершённая; любой канал с телом отчёта, dropped-строками или значением токена — reject среза.

## Consequences

**Positive**

- Класс ошибок «тихо неправильно» переводится в «громко и сразу»: неизвестный параметр даёт явную ошибку, а не отчёт не за ту неделю.
- Доказанный механизм пропуска недель (молчаливое игнорирование периода) закрыт на входе; `week_status` + ритуал снимают зависимость полноты от памяти владельца.
- Канонический формат рендера зафиксирован golden-гейтом до расширения каналов (B3/B4).
- Диагностика подключения (`health_check`, раздел A8) доступна без раскрытия секретов.

**Negative / neutral**

- Хендлеры вне генераторов остаются не-strict — принятый остаточный риск; write-тулзы уже имеют аудит required-параметров, вопрос — в следующей волне.
- Доки описывают live-preview до мержа кода-лейна; риск ограничен одной волной — ветки сходятся в одном релизе, V-прогоны идут на merged main.
- Сумма `week_status` может не совпадать с суммой отчёта (записи сб/вс вне окна рендера) — расхождение объясняется меткой в ответе тулзы, а не багом.
- Ритуал остаётся дисциплинарным (не автоматическим) до возврата `report_gaps`; триггер возврата зафиксирован — следующий пропущенный период.
- `Dropped lines` в md всегда «(0)» — читатель md-отчёта не видит отсечённые строки; документируется как конструкционное поведение.

## Alternatives considered

- **Тулза `report_gaps` в этой волне.** Отклонено: ритуал + `week_status` + сверка каталога закрывают детекцию дешевле; автоматизация-детектор отложена до реального рецидива, триггер возврата зафиксирован (следующий пропущенный период).
- **Окно `week_status` строго пн–пт.** Отклонено: теряет субботне-воскресные записи и даёт ложное «готово». Принято окно данных пн–вс с меткой «вне окна рендера» — одна строка отвечает и на «всё ли затрекано», и на расхождение сумм.
- **Sidecar-файл для dropped-строк.** Отклонено: лишний артефакт в дереве отчётов. Принят канал «секция в ответе тулзы + счётчик в лог без содержимого».
- **Strict-валидация на всех хендлерах сразу.** Отклонено: write-тулзы имеют собственный аудит required-параметров; скоуп сужен до генераторных хендлеров, остальные — отдельный вопрос следующей волны.
- **«Починим только доки, тихое игнорирование оставим».** Отклонено красной линией продукта: A1 (доки = реальность) и B5 (strict) неразрывны — без strict фикс доков деградирует при первом новом расхождении схемы.
